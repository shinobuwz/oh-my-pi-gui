# Spec：当前活 Pi session 的轻量浏览器 MVP

## 问题与目标

用户要轻量 Pi Web GUI，不要第二个开发工作台。首次可以从终端启动 GUI，之后受支持的日常聊天、标准问询、授权确认、停止与继续执行必须在浏览器完成，不要求回终端。

本 change 从交互兼容性原型继续到最小可用 GUI。用户现已明确同意首版暂缓 questionnaire 结构化表单，普通澄清通过聊天回复；该豁免不适用于授权确认，也不豁免问询状态通知与 reload 的浏览器闭环。

## 范围与非目标

- 本仓库内实现 Pi extension、受保护的 loopback bridge、本地单页浏览器界面。
- 同一 session 的聊天历史、流式回复、thinking/工具长输出折叠、多行输入、停止、steer/follow-up 的明确提交方式与状态。
- 主 agent 模型/thinking 切换并回显实际生效值；展示 cwd、Git 分支、用量与上下文数据，可用性不足时标未知而不是编造值。
- pi-subagents 只读列表、运行状态与详情按需展开；不另建调度器，不管理 agent/model 配置。
- 标准扩展对话框 confirm/select/input/editor 在浏览器回答；保留原返回类型、消费者 timeout/abort 与宿主问询生命周期通知。
- questionnaire 和任意 custom TUI 暂不适配，调用时明确报告不支持并安全失败。不复制或抢同名工具，不把聊天回复合成为该工具的结果。
- 不做工作区、文件管理、多会话、Web IDE、provider/凭据编辑、模型默认配置写入、独立发布或 OPSX 安装集成。
- 不修改已安装 Pi、OPSX 托管扩展、用户配置或授权策略。不新建主 runtime，不让另一进程读写当前 session 文件来模拟附着。

## 公共行为约定

### 会话与兼容边界

extension 附着宿主现有实例。已批准版本限定的非公开内部 UI 接缝，当前目标 Pi 0.85.1、pi-subagents 0.67.0；版本、接缝结构及实际绑定需验证。不匹配时拒绝启用 GUI 并明确报错，不静默降级终端。仅有类型、原型身份、文本检查或加载成功都不等于活 session 兼容。

Pi 内建配置/登录/会话选择器与任意扩展菜单不承诺自动适配；GUI 不暴露这些未支持的入口，不把不支持的命令作为普通模型提示偷偷执行。首次启动前已有模型凭据与项目运行环境仍由现有工具准备；启动后本 MVP 的受支持路径不能依赖终端菜单。

### 问询与授权

标准对话框由浏览器显式回答，原消费者收到原类型结果并继续；授权的同意与拒绝不可合并为泛化“继续”。所有原权限检查仍执行，不能绕过工具调用链。未知 custom TUI（含 questionnaire）在浏览器报告不支持、原调用明确失败且不挂起；不得回终端或自动批准。普通聊天问答不是结构化表单结果，也不是权限确认替代。

浏览器断线不销毁宿主、不批准、不透传终端；未结束请求留在宿主内存，重连恢复同一请求。原消费者 timeout/AbortSignal 继续有效，取消与过期以原方法非批准结果结束。重复、失效或类型不符的回答不得再次继续原流程。保留 Pi ui_prompt_start/end 的原始观察语义（包含并发/嵌套等待范围），不以自造事件冒充宿主事件。

### 浏览器重连与宿主生命周期

刷新和断线重连恢复当前会话状态。浏览器可发起本 session 的 reload，完成后无需复制新 URL/token 或终端操作即可重连；reload 期间不接受针对旧 extension ctx 的操作，旧问询安全结束，旧请求 ID/代际回答失效。授权凭据可以在同一宿主进程的连续浏览器连接中保留，但不能复用旧 session ctx 或把旧请求授权带入新代际。

进程内保留的桥接资源仅服务本宿主浏览器连接，不代表第二 agent/session 存储。reload 释放并重新绑定旧代际的处理器和会话引用，不重复监听或泄漏服务器；真正宿主 shutdown/quit 时清理服务器、内存状态与令牌。关闭浏览器本身不终止宿主及仍运行的子任务。跨宿主进程重启恢复不属首版保证。

### 聊天、模型与子任务数据

使用当前 Pi 的公开消息、模型、thinking 和只读 session 接口；消息交付时保留 skill/template 扩展语义，区分队列接受与真正执行。停止交给当前 ctx.abort，不直接杀宿主或子任务。历史使用当前有效分支，刷新与流式更新不重复记录，不直接写 session 文件；用户浏览历史时不强拉到底部。

候选模型遵循 scopedModels（空集合表示未限定，使用可用模型），不读取/发送 provider 凭据。setModel 返回 false 时显示失败，thinking 以宿主钳制后的实际值为准，不改默认配置。状态值取自公开数据或只读 Git 查询，不解析整条 TUI 状态栏，不把缺失量显示成真实零值。

子任务只走公开进程内 RPC/事件；fleet opaque key 与 run ID 分开，详情只针对可定位的 run。RPC 不可用、超时或无任务均有明确状态，不创建假数据；Main idle 不等于 child 完成。

### 本地安全

仅绑定 127.0.0.1，随机不可预测访问令牌认证。准确校验 Host/Origin、拒绝跨站写入、限制消息大小并校验操作与输入；使用 WebSocket 时校验握手和每条消息。资源本地提供、不用 CDN；不执行模型/工具输出中的 HTML/脚本，不开放任意文件读取、配置、凭据或任意方法调用 API。网页操作仅走明确列出的会话能力。测试权限确认用无外部副作用的消费者，不执行真实敏感操作。

## 整体方案与关键决策

采用 Node 内置能力和当前 vanilla 单页基础，先闭合标准问询、原始生命周期通知和同进程 reload，再补聊天/模型、最后接子任务只读面。版本限定 UI 适配可在 factory 准备，但 socket/timer 等长寿命资源从 session_start/明确命令开始。宿主及浏览器协议使用请求 ID 与代际控制；具体传输采用满足小规模本地使用的最小方案。

questionnaire 适配从实施依赖移除，不扩大私有工具执行拦截，不改 OPSX。unsupported 处理与 README 均明确这项用户已接受的限制，不能泛化为“所有扩展兼容”。

## 风险与验证边界

内部 UI 接缝随 Pi 升级易失效；reload 的资源生命周期与真实 bundle 运行形态需要消费者验证。实际浏览器/TUI 验收不可用时必须报告未验证，不以 fake DOM、未打包 runner 或 RPC 加载测试替代。依赖 questionnaire 才能完成的流程首版仍会失败，这是已接受范围限制而非实现成功。

## 整体验收标准

首次启动后，同一活 session 的聊天、模型/thinking、标准授权确认、停止、子任务详情、刷新/断线重连与 reload 均能在浏览器完成；不支持 questionnaire 的错误明确且不挂起。真实宿主消费者、HTTP/浏览器行为、安全拒绝与取消/过期均有证据。

完整验证包括 npm test、npm run check、真实活宿主与浏览器覆盖及两个独立只读审查；实际环境无法覆盖时不标最终通过。具体任务和场景见 [tasks.md](tasks.md)，重要依据和唯一最终结论见 [evidence.md](evidence.md)。
